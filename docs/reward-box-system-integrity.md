# 姫のごほうび金庫 — システム整合性とリリース条件

2026-10-16。目的は「修正の数」ではなく、ユーザーが日常的に使える整合したアプリを作ること。

## 単一の表示入口

| 機能 | 正式な実装 | 注意 |
| --- | --- | --- |
| キャラ選択・プロフィール・ショップ | `character-profiles.js` / `#cp-home` | 旧 `#page-shop` 等は旧スキル処理用の互換DOMとして一時保持。ユーザーには二重表示しない。 |
| 育成ポイント履歴 | `#canonical-point-history` / `wallet-upgrade.js` | `#cp-home` の直後に表示。取得/使用で切替。 |
| 画像編集 | `image-editor.js` | 正方形・円・横長の枠を画像上に重ね、指で動かし、角をドラッグして大きさを変更。各画面に独自クロッパーを増やさない。 |
| 画像保存 | `app-photos.js` | IndexedDB → 保存確認 → 描画。保存不可時は軽量化した画像を直接保存。成功前に完了表示しない。 |
| ファンド | `wallet-upgrade.js` | 既存のファンド規則を維持。旧 `renderFinance()` は互換処理のみ。 |
| ポイント算定 | `resource-ledger.js` | 初期残高 + 変更後の取引差分を記録。既存 `pointHistory` は過去の閲覧用に維持。 |

## 更新・保存の原則

1. `render()` は画面全体を一斉に再構築しない。選択中の画面を更新し、無関係な入力フォーム・写真プレビューの状態を保護する。
2. 写真は保存と読み戻しの成否を確認。画面は `AppPhotos.hydrate` でその場で表示更新する。
3. `resourceJournal` はバージョン、初期残高、追記型の取引を持つ。使用したポイントを記録編集で二重に取得しない。以前のデータの `resources` を改変しない。
4. リソース残高が負になる操作は拒否し、失敗した操作を履歴に残さない。
5. iOSの実機とデスクトップブラウザで動作が異なる可能性を認識し、テスト結果は環境ごとに分けて記録する。

## 自動テスト

- `npm run test:reward-box` — Nodeによる台帳・画像保存・切り抜き座標・資金移動のテスト。
- `npm run test:ui` — Playwright（390×844 mobile）による実際のUI操作。PRのCIではChromiumとWebKitで実行。
- GitHub ActionsはPRにテストとビルドを実施し、Pagesの配信はmainのみで行う。

## リリース判断

- [ ] Node/Chromium/WebKit CIに失敗がない。
- [ ] WebKit上で画像の切り抜き・保存・再起動、育成ポイント履歴と取得後の即時表示、設定変更とファンド入金を確認。
- [ ] iPhone Safari実機：同じ画像操作・一覧反映、キーボードのズーム・画面はみ出しを確認。
- [ ] 現在のブラウザ記録を書き出し、別環境の復元とデータ量を比較する。
- [ ] 本番更新後のrollback手順を明示する。

## 未解決・次フェーズで取り組むもの

- 旧UIの内部機能（スキル発動など）を正式UI側へ移してから互換DOMを完全削除する。
- ファンドの全履歴編集・訂正、以前の資金データの移行、借金返済の全ケースを統合テストで確認する。
- 過去のポイント履歴には取引IDがない記録があるため、現在の残高から以前の消費源を完全に復元することはできない。推測による書き換えはしない。
- iOS Safariでのみ発生する保存領域の制限、写真形式の違い（HEIC等）、画面ズーム・日付入力欄の表示は実機確認が必要。

**重要**：未検証事項を「完成」「確認済み」とは表記しない。
